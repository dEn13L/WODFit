# Продуктовая модель и границы

Текущая модель: тренер → программы → тренировки → задания → результаты атлетов. Только coach/client, без клубов. Уточнение/legacy title не возвращать в UI. Шаблоны и создание на основе не восстанавливать. Ограниченные возможности ниже требуют отдельной прямой задачи; декоративные согласованные встроенные изображения разрешены. Нормы UI — [AGENTS](../../AGENTS.md#ui-contract).

Сохранённые блоки ниже — первоисточник, а не самостоятельные текущие инструкции. Нормативный приоритет — корневой AGENTS и явная задача.

## Исходник: строки 43–60

```text
<!-- BEGIN source-043-060 -->
## 2. Продуктовая модель
Роли: coach (тренер), client (атлет). Клубов нет.
- Тренер ведёт тренировочные программы (programs): персональные (1 клиент) и групповые.
  Сущность «группа» УСТАРЕЛА и заменена на «программу» во всём проекте.
- Клиент вступает в программу по инвайт-коду (RPC join_program_by_code).
- Тренировка: название «Тренировка N», номер автоматически присваивается внутри
  программы при первом сохранении назначения (включая черновик). Дата/время
  остаются отдельными атрибутами. У неназначенного черновика номера нет.
  При нескольких программах без фильтра показываются пары программа/номер.
  Поле уточнения удалено; legacy workouts.title больше не показывается в UI.
- Тренировка состоит из заданий (workout_parts): название + свободное описание + порядок.
- Атлет вносит результат (part_results) по каждому заданию; формат записи выбирает
  атлет (part_results.score_type); один пользователь — один результат на задание
  (UNIQUE(part_id, user_id)).
- Клиент видит результаты других участников своей программы; тренер — все результаты
  своих тренировок.
- Шаблоны тренировок — УДАЛЁННАЯ фича (legacy-таблицы в БД, кода нет).

<!-- END source-043-060 -->
```
