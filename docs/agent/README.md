## Происхождение и проверка

Источник: `AGENTS.md` коммита `4fa4a19e1e327b1bebaaadbec0a0147d8e9f8e12`.
[Неизменяемый архив](../archive/AGENTS-4fa4a19.md) и
[SHA256](../archive/AGENTS-4fa4a19.md.sha256): 526 строк, 36115 UTF-8 символов,
58200 байт. [JSON manifest](source-map.json) покрывает каждую исходную строку
ровно одним primary тематическим назначением, включая пустые строки.
Архив не считается полезным тематическим переносом; проверяются сами source-блоки.
Сохраняются все байты между BEGIN/END, без нормализации Unicode/переносов/пробелов.
Manifest содержит диапазоны, SHA256 блока и целевые строковые/байтовые смещения.

```bash
python3 docs/agent/check_docs.py
git diff --check
```

[Checker](check_docs.py) — stdlib-only, read-only, не Flutter/SQL runner и не live аудит.
Проверяет archive/git identity, 526/526 первичных строк, блоки/смещения/хэши,
лимит 10000 символов, 18 UI номеров, обязательные permissions и локальные Markdown
ссылки/anchors новых документов плюс README/design brief. Исторический fenced текст
не парсится как новые ссылки. HTTP ссылки не проверяются сетевым запросом.
Перед каждым коммитом всё равно нужен чистый flutter analyze, затем релевантный CI.
Новый статус добавлять вне точных source-блоков, в той же feature PR; историю не
возвращать в постоянно загружаемый корень.

## Размер контекста Hermes

У Hermes startup-cap задаётся `context_file_max_chars`, иначе зависит от окна модели;
фиксированные 20000 не универсальны. Делегированному агенту нельзя рассчитывать
передать непоместившийся текст увеличением длины задания: context-файлы подчинены
лимитам загрузки, ссылки на справочники не читаются автоматически. Поэтому корень
держим до 10000 UTF-8 символов, детали открываем инструментами. Конфигурация/runtime
и skills в этой задаче не менялись. Это лимит проекта, не обещание token-бюджета.[1]

Sources:
- [1] [Официальные Hermes Context Files](https://hermes-agent.nousresearch.com/docs/user-guide/features/context-files)

## Состояние реорганизации

Корень сокращён; полный исходник сохранён в архиве и тематических source-блоках.
Проверки полноты и ссылок выполняются над установленным AGENTS.md, не кандидатом.
Изменены только документы и их read-only checker; код приложения, SQL и workflows
не изменялись. Live состояние не проверялось. Новые статусы добавлять вне source-блоков.
